# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Windows-only Spanish voice assistant. A docked side panel (pywebview window; can fold into a floating orb) shows today's agenda and the conversation, listens for a wake word, transcribes the question, sends it to Claude Code via `claude -p`, then speaks the answer and shows it in a side panel with visual "cards". All code, identifiers, comments, log messages and UI text are in Spanish — keep it that way.

## Running

There is no build step, test suite or linter. Dependencies live in `.venv` (Python 3.12); `requirements.txt` lists the direct ones (`.venv\Scripts\python.exe -m pip install -r requirements.txt`).

- `depurar.bat` — runs `asistente.py` with `python.exe` in a console (UTF-8), so logs are visible. Use this when debugging.
- `iniciar.bat` — runs with `pythonw.exe` (no console); output only goes to `asistente.log`.
- Equivalent: `.venv\Scripts\python.exe asistente.py`
- `inicio-automatico.bat` (or `inicio-automatico.bat quitar`) — creates/removes the Startup-folder shortcut; same `.lnk` the tray's "Iniciar con Windows" toggles.

Requires the `claude` CLI on PATH (or at `~/.local/bin/claude.exe`), Microsoft Edge (for screenshot cards), and a microphone.

## Architecture

Two Python modules plus a static web UI:

- **`motor.py`** — the engine, independent of the window. `Motor.ejecutar()` runs on a daemon thread: loads models, opens the mic stream, and loops over (1) typed questions from `Motor.textos`, (2) manual activation (`activar_manual` event), (3) wake-word detection. Pipeline per question:
  1. **Wake word**: Vosk (`modelos/vosk-model-small-es-*`) with the *full* vocabulary; the wake word is matched in word-level results against `confianza_minima`. Don't switch to a closed grammar — it forced every phrase to match the wake word (see comment in `ejecutar`).
  2. **Recording**: `grabar_pregunta()` does energy-based end-of-speech detection (noise floor from the first 300 ms, `segundos_silencio_fin`, `segundos_max_pregunta`).
  3. **STT**: `Motor.transcribir()` — faster-whisper (`modelo_whisper`, CPU int8, cached in `modelos/`; `HF_HUB_OFFLINE` is set once downloaded), `beam_size=5`, `initial_prompt` = config `vocabulario` + project folder names found by `buscar_proyectos()`. Low-confidence transcriptions (`avg_logprob` below `confianza_minima_transcripcion`) are discarded and the user is asked to repeat.
  3b. **Local fast path**: `atender()` first tries `acciones.atajo()` — regexes over normalized text (no accents/punctuation, ≤12 words) for time/date, volume (pycaw), media keys, podcasts/music on YouTube Music in the browser (`yt-dlp` search without API key; for podcasts it finds the channel and plays its newest video ≥15 min), opening Start-menu apps (`Get-StartApps` → `shell:AppsFolder`) or known sites, screen lock, timers (stored as local reminders with `temporizador`), weather (Open-Meteo, `ciudad` in `config.local.json`) today's/tomorrow's agenda/"buenos días" summary (plus one sentence on outages that started since the last activity, only if any), and service status ("cómo están mis servicios", "hay algo caído", "estado de los servidores" → `acciones.servicios()`: sentence + `tabla` of what isn't up; only when the vigía is configured). Returns a response dict (optionally `terminar` to skip follow-up, `despues` callable run after speaking) or None → Claude. Keep patterns strict so compound requests fall through to Claude. `acciones` imports `motor`, so `motor` imports it lazily.
  4. **Claude**: `correr_claude()` spawns `claude -p ... --output-format stream-json --verbose` and turns tool-use events into live progress. Question mode (`preguntar_a_claude()`) is read-only (`herramientas_permitidas`), runs in `carpeta_proyectos`, appends `SISTEMA` + current date/time, calendar/reminder instructions and the known project list, uses `modelo_pregunta`/`esfuerzo_pregunta` plus `--strict-mcp-config --setting-sources user` for a faster start, reuses the session via `--resume` within `minutos_contexto`, 300 s kill timer.
  5. **Response contract**: `SISTEMA`/`FORMATO` force JSON `{"voz", "detalle", "tarjetas", "tarea"?}`; `interpretar()` parses it and falls back to splitting plain text. Card types: `captura`, `imagen`, `codigo`, `estado`, `tabla`, `dato`, `fuentes`. Adding a card type means updating `SISTEMA`, `resolver_tarjeta()` (if it needs server-side work) and `construirTarjeta()` in `ui/app.js`.
  6. **Async cards**: `captura` (headless Edge screenshot into `capturas/`, embedded as data URI) and `estado` (HTTP ping) are resolved in a thread pool and pushed later as `tarjeta` events; the item is then saved to `historial.json` (last 100, without `src` blobs).
  7. **Tasks (two-phase)**: question-mode Claude never edits; when the user asks to *do* something it returns `tarea: {descripcion, carpeta, plan}` and asks for confirmation. `pedir_confirmacion()` waits for yes/no by voice (`es_si_o_no`), typed text, or UI buttons (`Motor.confirmaciones` queue). On yes, `lanzar_tarea()` runs a separate background `claude -p` in the project folder with `SISTEMA_TAREA`, `--permission-mode permisos_tarea` (default `auto`), `modelo_tarea`/`esfuerzo_tarea`, `herramientas_bloqueadas_tarea` as `--disallowedTools`, and a `minutos_max_tarea` limit. The main loop keeps listening; the result is queued in `Motor.avisos` and announced when idle, and a summary is prepended to the next question (`nota_contexto`) since the task session can't be resumed from `carpeta_proyectos`. "Cancela la tarea" (`CANCELAR_TAREA`) or the UI button kills it.
  8. **Follow-up**: after a voice-triggered answer, `seguimiento()` listens `segundos_seguimiento` s without the wake word (low-confidence transcriptions are ignored as noise); `atender()` returns False to end the conversation.
  9. **TTS**: edge-tts neural voice → `respuesta.mp3` played via MCI with word-boundary timings sent to the UI for highlighting; falls back to pyttsx3 (Windows SAPI). Mic audio captured while speaking is discarded.

- **`asistente.py`** — the shell: creates the frameless, always-on-top pywebview window, the system tray icon (pystray), the global hotkey (`keyboard`), and the "start with Windows" shortcut. Starts in `modo_inicial` (`panel`): `acoplar()` docks it full-height at the right edge, `ancho_panel` wide, and with `panel_fijo` registers it as a Win32 AppBar (`SHAppBarMessage`) so the work area shrinks and maximized windows don't go under it; `soltar_barra()` releases it on fold-to-orb, hide and exit. The registered hwnd is written to `modelos/panel-barra.txt` so a force-killed run's reservation is freed on next start (`limpiar_barra_huerfana()`). `vigilar_pantalla_completa()` drops topmost while another app is fullscreen. The orb mode still uses resize/move + Win32 regions. DPI: pywebview uses logical pixels while `webview.screens`, AppBar rects and Win32 regions use physical ones (`escala()`). At startup it deletes WebView2's HTTP cache (`modelos/webview/EBWebView/Default/Cache`), otherwise an old `index.html`/`app.js` is served after updates.

- **`calendario.py`** — local agenda, no cloud account. Events live in git-ignored `agenda.json` (`{"eventos": [{id, titulo, inicio, fin?, repetir?, hasta?, lugar?, descripcion?, recordatorio_min?, recordatorio?, creado}]}`; `inicio` is `AAAA-MM-DD` for all-day or `AAAA-MM-DDTHH:MM` local time; all-day `fin` is inclusive; written atomically). `listar(desde, dias, buscar)` expands recurrences (`diario|semanal|mensual|anual`, optional `hasta`) into occurrences with `inicio_real`/`fin_real`/`todo_el_dia`. Reading by Claude: the CLI `eventos --desde hoy|mañana|AAAA-MM-DD --dias N [--buscar texto]` prints one line per occurrence prefixed with `[id]`; `Motor.sistema()` documents the exact command (`motor.CALENDARIO`, forward-slash paths) and `Motor.herramientas()` adds a matching `Bash(<command> eventos:*)` allow rule. Writing: question-mode Claude returns `evento: {titulo, inicio, ...}` to create, `{id, <changed fields>}` to modify or `{id, borrar: true}` to delete (never writes itself); after the same yes/no confirmation as tasks, `Motor._crear_evento()` calls `crear_evento`/`modificar_evento`/`borrar_evento` and emits `agenda` to the UI. The panel's × button deletes directly (`Api.borrar`, with an inline confirm). Alerts: the main loop's `evento_por_avisar()` (every 20 s) speaks timed events `minutos_aviso_eventos` before (or `recordatorio_min`; `recordatorio: true` = at start time, 15 min long), only while the assistant is running and only within 5 min of the notice time. Already-spoken notices (`"id@inicio"` keys in `_avisados`) are persisted atomically to git-ignored `avisados.json` (pruned after 2 days) so a restart inside that window doesn't repeat them. Test directly: `.venv\Scripts\python.exe calendario.py eventos --dias 7`.

- **`vigia.py`** — read-only client + CLI for the «vigía», a service next to Uptime Kuma on another tailnet machine (`vigia_url` and `vigia_clave` in `config.local.json` — the repo is public, so `config.json` only has an empty `vigia_url` placeholder; the key is sent as `X-Clave`; `configurado()` is False if either is missing and everything service-related silently turns off). Functions `estado()`, `alertas()`, `incidentes(desde, hasta)` mirror `GET /api/estado|alertas|incidentes` (`/api/salud` needs no key); 5 s timeout; failures raise `ErrorVigia` with a speakable message ("No pude contactar al vigía") that never contains the URL or key. Real response fields are documented in each function's docstring — don't invent others. CLI for Claude: `estado [--todos] | alertas | incidentes --desde hoy|ayer|AAAA-MM-DD[THH:MM] [--hasta ...] [--dias N]` (local times, `--hasta` exclusive, one line per item). `Motor.herramientas()` adds `Bash(<python> <vigia.py>:*)` (`motor.VIGIA`) and `Motor.sistema_servicios()` adds the usage rules (exact weekend range computed in Python, last activity for "mientras no estaba", voice summary + `tabla` card). Test: `.venv\Scripts\python.exe vigia.py estado`.
  - **Alerts**: `Motor.vigilar_alertas()` runs on its own thread (started at the top of `ejecutar()`) so a dead vigía's 5 s timeout never stalls wake-word listening; every `segundos_revision_vigia` `revisar_alertas()` merges `/api/alertas` into `Motor.alertas`, persisted atomically in git-ignored `alertas.json` (`{id: {…, vista, reconocida, resuelta, anunciada}}`, resolved ones pruned after 30 days) so nothing repeats after a restart. Alerts are only marked resolved on a *successful* response; while the vigía doesn't answer the last known state is kept, and after 5 min a synthetic `vigia:sin_respuesta` (`atencion`) alert appears and resolves itself when it's back. Each change → `emitir`/`publicar` `{"tipo": "alerta", "accion": "nueva"|"resuelta"|"reconocida", "alerta"}`. New `critico` alerts are spoken once (`anunciada`), queued in `_por_decir` and said by the main loop only when idle and `Motor.bloqueo` is free; never with `alertas_voz` false, the mic muted, or inside `horario_silencioso` (then panel only). Criticals that began before startup are grouped in one sentence ("Mientras estabas fuera hubo 2 problemas críticos…").
  - **Last activity**: `atender()`/`atender_remoto()` call `registrar_actividad()`, which writes git-ignored `ultima_actividad.json` atomically but first keeps the previous value in `Motor.actividad_previa` (only after a >10 min gap, so it survives follow-ups). "Buenos días" (`acciones.novedades_servicios`) and the Claude prompt use it; read it, never the freshly written value.

- **Local voice reminders** — for short-term "recuérdame en 20 minutos", Claude returns `recordatorio_local: {texto, en_minutos | cuando}` (no confirmation) or `cancelar_recordatorios: [ids]`; pending ones are listed in the system prompt with their ids. Stored in git-ignored `recordatorios.json`, fired by the main loop when idle (`recordatorio_vencido()` / `recordar()`); ones missed while the PC was off are announced as late on next start.

- **`remoto.py` + `ui-remoto/`** — phone access over Tailscale. A threaded bottle/wsgiref server on `127.0.0.1:puerto_remoto` (started from `Motor.ejecutar()` once Whisper is loaded, only if `clave_remota` is set in `config.local.json`), published inside the tailnet with `tailscale serve --bg --https=8443 8765` (port 443 on this PC's Tailscale IP is taken by a Docker container). Every request needs the key (`X-Clave` header or the HttpOnly cookie set by `/?clave=...`). API: `/api/preguntar` (JSON texto), `/api/audio` (raw recording → Whisper), `/api/confirmar`, `/api/novedades?desde=n` (poll; also carries `alertas` = `Motor.estado_alertas()` for the red band in `ui-remoto` listing unacknowledged criticals, each with a «Visto» button), `/api/alertas` (same summary), `/api/reconocer` (POST `{id}` → `Motor.reconocer_alerta`; the band's «Visto» buttons, one per critical), `/api/voz?t=` (edge-tts MP3). `Motor.atender_remoto()` mirrors `_atender()` but returns the response instead of speaking; confirmations are two-step via `pendiente_remoto`; progress, resolved cards, finished tasks and fired reminders go to the `Motor.buzon` the page polls. `Motor.bloqueo` (RLock) serializes PC and phone conversations; `bloqueo_whisper` guards the model. In remote mode Claude is told not to use `recordatorio_local`, and `acciones.reproducir` returns a link (`abrir`) instead of opening the PC browser.

- **`ui/`** (`index.html`, `app.js`, `app.css`, vendored highlight.js) — plain JS, no framework or bundler. The panel has, from the top, the collapsible "Servicios" section (`#servicios`, only when the vigía is configured: one-line summary — "36 servicios · todo en orden" in green or the problem count —, critical alerts in red and attention ones in amber, each with since-when and a «Visto» button → `Api.reconocer`; unacknowledged criticals stay visible even when folded; fold state in localStorage; reloads on the `alerta` event and every 60 s via `Api.alertas()`), then the day timeline (`#dia`: ‹ › day navigation, "Sigue/Ahora" banner, now-marker, fold state in localStorage) above the conversation; it reads `Api.agenda(dia)` (agenda events + local voice reminders) and repaints every 30 s.

### Python ↔ UI bridge

- Python → JS: `motor.emitir(evento)` (replaced at startup by `asistente.emitir`) calls `window.app.on(evento)` via `evaluate_js`. Events are dicts keyed by `tipo`: `estado`, `nivel`, `pregunta`, `progreso`, `respuesta`, `palabras`, `tarjeta`, `confirmar`, `confirmado`, `tarea`, `aviso`, `silenciado`, `limpiar`, `abrir_panel`, `agenda` (reload the day; optional `dia` to jump to and `resaltar` id to flash), `alerta` (`accion` nueva/resuelta/reconocida + `alerta`; reloads the services section, a new critical opens the panel), `modo`. Handled in the `switch` in `app.js`.
- JS → Python: `window.pywebview.api.<method>` maps to methods of the `Api` class in `asistente.py` (`alertas()` → `Motor.estado_alertas()`, `reconocer(id)` → `Motor.reconocer_alerta()`).

## Configuration

`config.json` is read once at import (`motor.CFG`) and overlaid with the git-ignored `config.local.json` (personal data and secrets: `ciudad`, `clave_remota`, `vigia_url`, `vigia_clave`; template without values in `config.local.ejemplo.json`); restart after changes. `vigia.py` reads both files itself (it runs as a standalone CLI). Vigía keys in `config.json`: `vigia_url` (empty; the real one goes in `config.local.json`), `segundos_revision_vigia` (60), `alertas_voz` (true), `horario_silencioso` (`["23:00", "07:00"]`, may cross midnight). Notable keys: `palabra_activacion`, `confianza_minima`, `carpeta_proyectos` (Claude's working directory for questions and root for project discovery), `herramientas_permitidas` (question mode — keep read-only; edits must go through the confirmed task flow), `vocabulario`, the `*_tarea` keys, `motor_voz`, `atajo`, `modo_inicial`, `panel_fijo`, `ancho_panel`, `minutos_aviso_eventos`, `segundos_ocultar` (0 = the panel never folds itself).

## Generated / runtime files

`asistente.log`, `historial.json`, `agenda.json` (user data — don't delete), `recordatorios.json`, `alertas.json`, `ultima_actividad.json`, `avisados.json`, `respuesta.mp3`, `capturas/` (PNGs pruned after 7 days), and `modelos/` (Vosk/Whisper models, Edge headless profile, WebView2 storage) are runtime data — don't edit or search them.
